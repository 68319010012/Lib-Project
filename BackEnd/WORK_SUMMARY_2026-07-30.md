## 1. รันโปรเจกต์ผ่าน XAMPP

- เปิด MySQL ใน XAMPP (ไม่ต้องเปิด Apache เพราะเว็บรันผ่าน Flask dev server โดยตรง)
- ตรวจสอบฐานข้อมูล `library_checkin` ว่ามีตาราง `students`, `users`, `checkin_logs` ครบ
- รัน Flask server จาก venv ที่มีอยู่แล้ว (`python app.py`) — เข้าใช้งานได้ที่ `http://127.0.0.1:5000`

## 2. แปลเว็บทั้งหมดเป็นภาษาไทย

แปล UI ทุกหน้าที่ยังเป็นภาษาอังกฤษ ให้เป็นภาษาไทยทั้งหมด:

- `login.html` — เข้าสู่ระบบ, แท็บนักศึกษา/แอดมิน, ปุ่ม, ข้อความ error
- `signup.html` — สมัครสมาชิก, ฟอร์มทั้งหมด, ข้อความแจ้งเตือน
- `dashboard.html` — หน้าหลักนักศึกษา, ปุ่มเช็คอิน/เช็คเอาต์, ประวัติการเข้าใช้
- `admin_dashboard.html` — แดชบอร์ดแอดมิน, สถิติ, กราฟ, heatmap
- `members_management.html` — หน้าจัดการสมาชิก, ตัวกรอง, ตาราง
- `attendance_logs.html` — ประวัติการเข้าใช้ทั้งหมด, ตัวกรอง, ตาราง
- `edit_profile.html` — แก้ไขโปรไฟล์, เปลี่ยนรหัสผ่าน
- `app.py` — ข้อความ error ที่ backend ส่งกลับ (เช่น "invalid username or password" → "ชื่อผู้ใช้หรือรหัสผ่านไม่ถูกต้อง") เพื่อให้ error ที่ขึ้นหน้าเว็บเป็นภาษาไทยด้วย
- เทมเพลตรายงานสำหรับพิมพ์ (`report_daily.html`, `report_monthly.html`, `report_department.html`) เป็นภาษาไทยอยู่แล้วจากเดิม

## 3. เปลี่ยนชื่อแผนกวิชา

- อัปเดตฐานข้อมูล: นักศึกษา 132 คนที่อยู่แผนก **"คอมพิวเตอร์"** → เปลี่ยนเป็น **"เทคโนโลยีธุรกิจดิจิทัล"**
- อัปเดต dropdown เลือกแผนกวิชาในหน้าสมัครสมาชิก (`signup.html`) ให้ตรงกับชื่อใหม่

## 4. หน้าแอดมิน — ไม่มีการสมัครบัญชี

- แก้หน้า login: เมื่อเลือกแท็บ **"แอดมิน"** ลิงก์ "สมัครสมาชิก" จะถูกซ่อนอัตโนมัติ (ยังคงแสดงตามปกติเมื่อเลือกแท็บ "นักศึกษา")
- ไม่มีการเพิ่มช่องทางสมัครบัญชีแอดมินผ่านเว็บ — สร้างได้เฉพาะทาง `create_admin.py` บนเครื่อง server เท่านั้น (เหมือนเดิม เพื่อความปลอดภัย)

## 5. ตัดช่องเลือก Username ออกจากหน้าสมัครสมาชิก

- เอาช่อง "Choose a Username" ออกจากฟอร์มสมัครสมาชิก
- ระบบใช้ **รหัสนักศึกษาเป็นชื่อผู้ใช้ (username) โดยอัตโนมัติ** แทน — นักศึกษาไม่ต้องตั้งเอง ล็อกอินด้วยรหัสนักศึกษา + รหัสผ่านที่ตั้งไว้
- แก้ `app.py` route `/register`: เอา validation ของ username ออก, ใช้ `student_id` เป็น `username` ตรงๆ

## 6. สร้างบัญชีแอดมิน

- สร้างบัญชีแอดมินผ่าน `create_admin.py` — username: `admin`
- **คำแนะนำ**: ควรเปลี่ยนรหัสผ่านนี้เองหลังใช้งานจริง หรือสร้างบัญชีแอดมินใหม่ด้วยคำสั่ง `python create_admin.py <username>` แล้วลบบัญชีเก่าออกจากฐานข้อมูลถ้าต้องการ (รหัสผ่านที่ตั้งไว้ตอนนี้เคยถูกพิมพ์ในแชท จึงไม่ปลอดภัย 100% แนะนำเปลี่ยนใหม่)

## 7. ฟีเจอร์ใหม่: รายงานแบบแดชบอร์ด

เพิ่ม route และเทมเพลตใหม่สำหรับพิมพ์/ส่งออกรายงานแบบแดชบอร์ด (ตามภาพตัวอย่าง Google Data Studio ที่ให้มา):

- Route ใหม่: `/admin/reports/print/dashboard?month=YYYY-MM`
- แสดง KPI การ์ด 4 ใบ (จำนวนรายการทั้งหมด, นักศึกษาไม่ซ้ำคน, เฉลี่ยต่อวัน, วันที่มีคนใช้มากที่สุด)
- กราฟแท่งแนวโน้มรายวันตลอดทั้งเดือน
- กราฟแท่งแผนกที่เข้าใช้มากที่สุด (top 8)
- ทำด้วย CSS ล้วน (ไม่พึ่ง JS chart library ภายนอก) เพื่อให้พิมพ์/ส่งออก PDF ได้เสถียรแม้ไม่มีอินเทอร์เน็ต
- ไฟล์ใหม่: `templates/report_dashboard.html`

## 8. ปรับปรุงหน้า "เลือกเทมเพลตรายงาน"

- ออกแบบใหม่ทั้งหมด (`reports_select.html`) จากหน้า plain HTML ธรรมดา เป็นการ์ดสีสัน มีไอคอน, hover effect, ใช้โทนสีเดียวกับเว็บหลัก
- **แก้บั๊ก**: การ์ดมีขอบ (border) แต่มองไม่เห็นเต็มจนกว่าจะเอาเมาส์ไปชี้ — สาเหตุคือ `header` ที่มี `position: relative` (สำหรับทำลายจุดพื้นหลัง) สร้าง stacking context ที่ทับซ้อนอยู่เหนือการ์ดที่ซ้อนขึ้นไปใต้ header (negative margin overlap) พอ hover แล้ว `transform` ทำให้การ์ดนั้นได้ stacking context ของตัวเอง เลยโผล่มาเหนือ header — แก้โดยเปลี่ยนวิธีทำลายพื้นหลังจาก pseudo-element (ที่ต้องใช้ `position:relative`) เป็น layered `background-image` แทน ทำให้ header ไม่ใช่ positioned element อีกต่อไป ปัญหาหายไป
- เพิ่ม responsive breakpoints สำหรับจอมือถือ/แท็บเล็ต

## 9. ปรับปรุงเทมเพลตพิมพ์รายงานทั้งหมด (`base_print.html`)

ปรับใหม่จากหน้าเปล่าๆ มีแค่กรอบ ให้มีดีไซน์และ responsive:

- เพิ่ม `<meta viewport>` (ของเดิมไม่มี ทำให้เปิดจากมือถือแล้วต้องซูม/เลื่อนเอง)
- ใส่ header แบรนด์สีแดงเลือดหมู (โทนเดียวกับเว็บหลัก), ตารางมีสีหัวตาราง + เส้นสลับสี (zebra striping)
- ตารางมี scroll แนวนอนได้บนจอเล็กแทนที่จะล้นจอ
- ปุ่ม "พิมพ์ / บันทึกเป็น PDF" และ "เลือกเทมเพลตอื่น" ออกแบบใหม่ให้เข้าธีม
- `@media print` ยังคงบังคับให้เป็นสีอ่อน/ประหยัดหมึกตอนพิมพ์จริงเหมือนเดิม
- มีผลกับ `report_daily.html`, `report_monthly.html`, `report_department.html`, `report_dashboard.html` ทุกหน้า (extends จาก `base_print.html` เดียวกัน)

## 10. โหมดมืด/สว่าง (Dark / Light Mode) ทั้งเว็บ

เพิ่มปุ่มสลับโหมดมืด-สว่างในทุกหน้าที่ผู้ใช้เข้าถึงได้ (ไม่รวมหน้ารายงานที่พิมพ์ เพราะพิมพ์ควรเป็นสีอ่อนเสมอ):

- `login.html`, `signup.html`, `dashboard.html`, `edit_profile.html`, `admin_dashboard.html`, `members_management.html`, `attendance_logs.html`
- ปุ่มสลับ (ไอคอนพระอาทิตย์/พระจันทร์) — กดแล้วจำค่าไว้ใน `localStorage` เปิดครั้งต่อไปจะจำโหมดเดิมไว้ให้อัตโนมัติ
- ถ้ายังไม่เคยกดปุ่มเลย ระบบจะดูจาก **การตั้งค่าโหมดมืด/สว่างของเครื่อง** (`prefers-color-scheme`) เป็นค่าเริ่มต้น
- มี inline script เล็กๆ ที่หัวหน้าเว็บทุกหน้า ทำงานก่อนหน้าเว็บวาดผล เพื่อไม่ให้เห็นหน้าจอกระพริบสีตอนโหลด (anti-flash)
- โทนสีมืดที่ใช้: พื้นหลังดำอมแดงเข้ม (`#141112`), การ์ด/พาเนล (`#1f191b`), เส้นขอบ (`#4a3a3c`), ตัวอักษรรอง (`#c9b8ba`) — เข้ากับธีมสีแดงเลือดหมู/ส้มของเว็บเดิม
- ฟังก์ชันสลับธีม (`initThemeToggle`) อยู่ใน `static/js/api.js` ใช้ร่วมกันทุกหน้า
